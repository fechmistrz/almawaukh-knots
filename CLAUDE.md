# CLAUDE.md

Instructions for working on this repository.
This file follows its own formatting rule: one sentence per line, no hard wrapping.

## What this repository is

A Polish-language book on knot theory ("Przewodnik po teorii węzłów"), written in LaTeX.
It started as a translation of notes by C. Allard and A. Gauthier and has grown into something between a survey, lecture notes and a textbook.
The prose is in Polish; code, tooling, commit messages and PR descriptions are in English.
[README.md](README.md) describes the book's contents; [src/README.md](src/README.md) is the original contributor guide (in Polish) and remains authoritative where it is more specific than this file.

## Layout

- `src/knot-theory.tex` is the main file; it `\input`s every chapter in order, so a new file is not part of the book until it is added there or to its parent section file.
- `src/00-meta-latex/` holds macros (`shortcuts.tex`) and diagram infrastructure (`diagrams.tex`, generated `new_diagrams.tex`).
- `src/10-introduction/`, `src/20-primeness/`, `src/30-invariants-numeric/`, `src/40-colours/`, `src/40-topology/`, `src/50-polynomials/`, `src/50-families/` are the prose chapters.
- File names carry their position in the book (`301-numerical_invariants.tex`, `301a-crossing.tex`, `301ba-unknotting_one.tex`); a parent file such as `301-...` `\input`s its `301a-...`, `301b-...` children.
- `src/90-appendix/` holds the appendix: tables, notation, the Polish–English dictionary.
- `src/knot_theory.bib` is the single bibliography.
- `src/include/` holds the front matter (`head_*.tex`) and back matter (`foot.tex`).
- `src/merridew/` is a git submodule (`fechmistrz/merridew`) with the document class and bibliography helpers; do not edit it from this repository.
- `tools/` holds Python, Ruby and shell helpers for generated content, linting and spellchecking.
- `src-build/` is a throwaway copy of `src/` made by `make`; never edit it.
- `src/` contains stray LaTeX build artifacts (`*.aux`, `*.log`, `*.pdf`, ...); they are gitignored, leave them alone.

## Generated files: do not edit by hand

These are committed to git but regenerated by `make` or `make lint`; change the generator or its input instead.

- `src/00-meta-latex/new_diagrams.tex` comes from `tools/diagram_rules/*.py` via `tools/write_diagram_rules.py`.
- `src/00-meta-latex/citation_count.tex` comes from `tools/count_citations.py` (defines `\citationcount`).
- `src/90-appendix/table_invariants.tex` and `table_invariants_summary.tex` come from `tools/convert_knotinfo_json_to_table.py` and `tools/knotinfo_parsed.json`, which in turn comes from `tools/knotinfo_raw.txt`.
- `src/90-appendix/dictionary.tex` comes from the `% DICTIONARY;...` comments scattered through the prose (see below), collected by `make lint`.

## Building and checking

- `make` (or `make all`) builds `knot-theory.pdf` with LuaLaTeX and BibTeX in `src-build/` and copies the PDF to the repository root.
- `make all-fallback` builds directly inside `src/` without `rsync`.
- `make test` checks bibliography author names (`tools/verify_bib_authors.py`) and runs the Polish spellchecker (`tools/spellcheck.sh`, aspell over `src/[12345]*/*.tex`).
- `make lint` sorts the `.bib` file, strips non-breaking spaces and tabs, collapses repeated blank lines in `.tex` files, regenerates the dictionary, and reports unused `\label`s and uncited `.bib` entries.
- `make clean` removes `src-build/`, `tmp/` and PDFs.
- If the submodule is missing, `make` runs `git submodule update --init` itself.
- After changing prose, run `make test`; after changing labels, citations, dictionary comments or file formatting, also run `make lint` and commit what it rewrites.
- When `make test` flags a correct word (a Polish word, a technical term, a surname), add it to `tools/aspell-pl.pws`, one word per line.
- Do not claim a change builds unless you ran the build; if LuaLaTeX is unavailable, say so.

## Source formatting

- One sentence per line in `.tex` and `.md` files.
- There is no maximum line length; never hard-wrap or reflow prose, and do not re-wrap lines you did not otherwise change.
- Indent with 4 spaces, never tabs (`make lint` converts tabs anyway).
- Do not use non-breaking space characters (U+00A0); use `~` instead.
- No more than one blank line in a row.
- Keep diffs minimal: change the sentences that need changing and leave surrounding lines byte-for-byte identical.

## Polish typography

- Tie single-letter words to the next word with `~`: `w~`, `z~`, `i~`, `o~`, `u~`, `a~` (the existing text is not fully consistent; follow the rule in new or edited lines, but do not sweep unrelated lines).
- Quotation marks are `,,tekst''` (two commas, two apostrophes).
- A dash between words is ` -- ` with spaces around it; `---` and literal `–` are rare and should not be added.
- Page ranges inside `\cite` use a plain hyphen: `\cite[s. 455-465]{ohtsuki2002}`.
- Write century and decade references the way the text does: `XX wieku`, `latach 80. XX wieku`.
- Surnames are declined in Polish (`u~Ohtsukiego`, `Bergera`, `Fenna, Rourkego`); use the established declension when a name already appears in the text.
- Russian names are transliterated in Polish style (Matwiejow, Wasiljew, Koncewicz, Chowanow), with the original Cyrillic in the persons index.

## Mathematical notation

Use the macros from `src/00-meta-latex/shortcuts.tex` instead of spelling notation out by hand, and keep notation consistent with `src/90-appendix/notation.tex`.

- Number sets: `\N`, `\Z`, `\Q`, `\R`, `\C`.
- Connected sum: `\shrap` (and `\bigshrap`).
- Polynomials: `\alexander` (Δ), `\conway` (∇), `\jones` (V); HOMFLY-PT is `P`, Kauffman is `F`, BLM/Ho is `Q`.
- Kauffman bracket: `\bracket{...}`.
- Invariants as operators: `\crossing`, `\unknotting`, `\bridge`, `\braid`, `\linking`, `\writhe`, `\genus`, `\stick`, `\ropelength`, `\volume`, `\sign`, `\trace`, `\ColoringGroup`.
- Mirror and reverse of `K` are `\operatorname{m} K` and `\operatorname{r} K`.
- The image of a set under a function is written `f[X]`, not `f(X)`; maps use `f \colon X \to Y`.
- Number of p-colourings is `\tau_p`; signature is `\sigma`.
- If a symbol is used in a formula, make sure it was introduced earlier in the text; undefined variables are a recurring class of bug in this book.

## Theorem environments and labels

- Available environments include `definition`, `proposition`, `corollary`, `lemma`, `theorem`, `conjecture`, `example`, `remark`, `proof`; `proposition` is by far the most common for stated results.
- The optional argument names the defined term or the result, in Polish: `\begin{definition}[splot alternujący]`, `\begin{proposition}[warunek Murasugiego]`.
- Label prefixes: `def:`, `prp:`, `cor:`, `lem:`, `thm:`, `con:`, `eqn:`, `sec:`, `sub:`; prefer these over ad hoc ones such as `prop:`.
- Every `\label` should be referenced by some `\ref` or `\pageref` (`make lint` reports orphans).
- The environment name in `\begin` must match `\end` and should match the kind of statement it is.

## Citations and bibliography

- Cite sources whenever a fact is not folklore; this book is heavily referenced.
- Page and item locators are in Polish: `\cite[s. 11]{burde2014}`, `\cite[s. 455-465]{ohtsuki2002}`, `\cite[tw. 3.2]{...}`, `\cite[wniosek 4]{...}`, `\cite[problem 1.5]{...}`.
- Bib keys are the first author's surname plus the year: `nelson2016`, `fenn1992`; double-check the year in the key against the entry.
- Bib entries follow the MathSciNet style with uppercase field names (`AUTHOR`, `TITLE`, `MRNUMBER`, ...) and braces around capitals in titles (`{K}leeblattschlingen`).
- Authors are written `Surname, Given names` and the same person must be spelled identically everywhere (`tools/verify_bib_authors.py` checks this).
- Every `.bib` entry must be cited at least once; do not add entries you do not cite, and prefer fixing a citation over deleting a legitimate entry.
- Web sources that are not in the bibliography go in a `\footnote{...}` with `\url{...}`.
- Do not hardcode the number of citations; use `\citationcount`.

## Indexes

There are separate indexes for terms (`\index{...}`) and for people (`\index[persons]{...}`).

- Put each `\index` command on its own line, directly after the sentence where the term or person appears, and end it with `%` so it does not insert a space.
- Persons are indexed as `\index[persons]{Surname, Given name}%`, with the full given name; for Russian names add the Cyrillic original in parentheses, e.g. `\index[persons]{Matwiejow, Siergiej (Матвеев, Сергей Владимирович)}%`.
- Subentries use `!`: `\index{bukszpan!gwieździsty}%`.
- A term discussed over several pages is opened with `\index{term|(}%` and closed with `\index{term|)}%`.
- Synonyms point to the main entry: `\index{grupoid rozdzielny|see {kwandel}}%`.
- Before inventing a new index term, search for an existing one for the same concept and reuse it.

## Polish–English dictionary

Knot-theory terms should have their English equivalent recorded in a comment next to their first use:

```
% DICTIONARY;yummy;smaczny;bulbulator
```

- The fields are `english;polish;context`, where context is the related term or `-` if there is none.
- `make lint` turns these comments into `src/90-appendix/dictionary.tex`.
- Prefer the Polish term already used in the book (e.g. `węzeł ilorazowy`, not a calque like `faktor`); if an English term has no Polish equivalent yet, check the dictionary before coining one.

## Diagrams

- Knot diagrams in TikZ use `ultra thick` lines, except in proofs in the Kauffman bracket section, which use `thick`.
- Reusable small diagrams (Reidemeister moves, chord diagrams, skein triples, ...) are defined in `tools/diagram_rules/*.py` as `diagram_commands[...]` dicts and compiled into `new_diagrams.tex`; add new reusable diagrams there rather than inline.

## Content conventions

- Mention people with their contribution and year where relevant, and index them.
- Keep the book's existing scope; if a topic is intentionally omitted (e.g. Floer homology), say so in the text rather than half-explaining it.
- Author notes and open questions go in LaTeX comments starting with `% TODO:` in Polish; do not leave visible placeholders such as `(do napisania!)` in the output.
- Large blocks of draft or excluded text are wrapped in `\begin{comment}...\end{comment}`.
- When fixing a mathematical statement, check it against the cited source and fix the proof and any dependent statements too.
- `src/README-todo.txt` and `todo-citations.txt` are scratch notes and leads for future work, not part of the book.

## Git workflow

- Never commit to `master` directly; work on a branch named `dev/claude-<short-topic>` (e.g. `dev/claude-lissajous-faktor`).
- One logical change per branch and PR; keep unrelated fixes out.
- Commit subjects are short, imperative, in English, and name what changed in the book: `Fix parity typo and introduce J in Lissajous Alexander proof`.
- If the change addresses a GitHub issue, end the subject with `(issue #N)`.
- The commit body explains why the change is correct (the mathematical argument, the source consulted, what was verified), wrapped at about 72 columns.
- Do not commit build outputs (`*.pdf`, `src-build/`, `*.aux`, ...) or unrelated untracked files in the working tree.
