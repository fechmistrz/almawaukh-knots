# Instructions for Claude

## The project

This repository holds Polish-language notes on knot theory, written in LaTeX.
They started as a translation of the French notes by C. Allard and A. Gauthier and have grown into something between a survey, lecture notes and a textbook.
The prose of the notes is in Polish, and new text must be in Polish too.
The LaTeX sources live in `src/`, grouped into numbered chapter directories such as `src/10-introduction` and `src/50-polynomials`.
The main file is `src/knot-theory.tex`, and the bibliography is `src/knot_theory.bib`.
Helper scripts live in `tools/`, and images and data files live in `data/`.

## Writing style

Put one sentence per line in every `.tex` file, and in this file too.
Never wrap a sentence across several lines, and never put two sentences on one line.
Follow the conventions described in `src/README.md`.
Put `\index{...}%` on the line right after the sentence that introduces the term, and use `\index[persons]{Surname, Name}%` for people.
Give every knot-theory term its English equivalent with a `% DICTIONARY;english;polish;-` comment, because `make lint` builds the pl-en dictionary from these comments.
Write English terms in the running text as `\textsc{...}`.
Draw TikZ knot diagrams with `ultra thick` lines, except in the proofs in the Kauffman bracket section, which use `thick`.
Match the surrounding text in tone, notation and macros, and look up existing macros in `src/00-meta-latex/shortcuts.tex` before defining new ones.

## Building and checking

`make` builds `knot-theory.pdf` with LuaLaTeX and BibTeX inside a copy of the sources in `src-build/`.
The build needs the `src/merridew` submodule, which is fetched with `git submodule update --init`.
`make test` checks the authors in the bibliography and runs the Polish aspell spellcheck.
If aspell flags a correct word, such as a technical term or a name, add it to `tools/aspell-pl.pws` and keep the word count on the header line in sync.
`make lint` sorts the bibliography, normalises whitespace, refreshes the dictionary and reports unused labels and uncited bibliography entries.
Some files are generated by `make`, such as `src/00-meta-latex/new_diagrams.tex`, `src/00-meta-latex/citation_count.tex` and the invariant tables in `src/90-appendix/`, so change their generators in `tools/` rather than editing them by hand.
Run the build and the checks before pushing, and if a tool is missing in the environment, say so instead of claiming that the build passed.

## Git workflow

Work on a separate branch and merge it into `master` through a pull request.
Keep each commit focused on one change and describe that change in the commit message.
When a change addresses a GitHub issue, mention the issue number in the commit message.

## Using other people's notes

The user sometimes brings in other lecture notes to compare with these ones, for example `knots34-b.pdf` from a lecture course at the University of Gdańsk.
Such notes belong to their authors, so never commit them to this repository.
Keep them outside the repository, for example in the scratchpad directory.
Use them only as a reference for finding gaps, errors and better explanations in these notes.
Never copy text from them, and always write new material in your own words in Polish.
Propose a list of possible improvements first, and edit the notes only after the user has chosen which ones to make.
When an idea comes from such notes, ask the user whether to credit the author in `src/knot_theory.bib`.
